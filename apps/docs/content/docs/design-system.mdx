The look of the app is going to change while we build it. We want a change of accent colour or corner radius to be an edit to one file, not a search through every screen.

The tokens live in `packages/tokens/tokens.json`. The visual design itself is not final.

## Tokens

A token is a named design value. Screens and components use the name and never the raw value.

Tokens are named by what they are for, not by what they look like. A screen asks for `colors.textMuted`, not `grey500`. If muted text later becomes a warmer grey, the name still makes sense and no screen has to change.

| Group | Examples |
| --- | --- |
| Colour | `colors.background`, `colors.surface`, `colors.border`, `colors.text`, `colors.textMuted`, `colors.accent` |
| Type | `typography.title`, `typography.heading`, `typography.body`, `typography.button`, `typography.caption`, `typography.numberLarge` |
| Spacing | `space.xs`, `space.s`, `space.m`, `space.l`, `space.xl`, `space.xxl` |
| Radius | `radius.control`, `radius.panel` |
| Size | `size.control` |
| Motion | `motion.quick`, `motion.standard` |

## One source for every app

The tokens live in one file, `packages/tokens/tokens.json`. A build step turns that file into what each platform needs.

| App | Generated output |
| --- | --- |
| iOS | Swift constants |
| Android | Kotlin constants |
| Website and docs | CSS variables |

Only the iOS output is needed to start. The others get added when those apps begin. `pnpm tokens:build` runs `packages/tokens/build.mjs` to write the output, and `pnpm tokens:check` fails if a generated file is out of date.

## Components sit on top of tokens

Each app has a small set of shared components, such as a button, a set row and a rest bar. Components are the only place tokens get used directly. Screens are built from components.

That gives three layers, and each one only knows about the layer below it.

1. Tokens hold the values.
2. Components use tokens.
3. Screens use components.

## Rules

- No raw colours, font sizes, spacing values or radii in a screen or a component. If the value you need does not exist, add a token.
- A token is added in `tokens.json` first, then used. Nobody edits generated files by hand.
- If two components need the same new value, that is a sign it should be a token and not a one-off.

## Starting values

These are the values in the current mock-ups. They are here so the first build has something to use, and we expect them to change.

| Token | Value |
| --- | --- |
| `colors.background` | `#0A0A0A` |
| `colors.surface` | `#151515` |
| `colors.border` | `#262626` |
| `colors.text` | `#F2F1EE` |
| `colors.textMuted` | `#8E8E8A` |
| `colors.accent` | `#C8B698` |
| `radius.control` | 8 |
| `radius.panel` | 12 |
| `space.xs` to `space.xxl` | 4, 8, 12, 16, 20, 24 |
| `size.control` | 52 |

The app uses one typeface in light, regular and medium weights. Which typeface is still open. The choice is between the iOS system font and one we bundle with the app.
