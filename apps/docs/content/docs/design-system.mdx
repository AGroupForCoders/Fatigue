The look of the app changes while we build it. We want a change of accent colour or corner radius to be an edit to one file, not a search through every screen.

The tokens live in `packages/tokens/tokens.json`. A build step turns that file into `apps/ios/Fatigue/DesignSystem/Tokens.swift`, and the iOS app reads every design value from there.

## Tokens

A token is a named design value. Screens and components use the name and never the raw value.

Tokens are named by what they are for, not by what they look like. A screen asks for `foregroundMuted`, not `grey500`. If muted text later becomes a warmer grey, the name still makes sense and no screen has to change.

| Group | What it holds |
| --- | --- |
| `fontFamily` | The one typeface every text style uses. Inter, bundled with the app in Light, Regular and Medium. |
| `themes` | One palette per theme. Every theme names the same colours. See [themes](#themes). |
| `defaultThemes` | Which theme stands in for plain light and plain dark when the choice is "system". |
| `typography` | `title`, `exerciseName`, `number`, `numberLarge`, `timer`, `body`, `control`, `button`, `caption`, `label`. Each is a size in points, a weight and a tracking in em. |
| `space` | `xs` to `xxxl`: 4, 8, 12, 16, 20, 24, 32. |
| `radius` | `control` 8, `tick` 7, `panel` 12. |
| `size` | Control heights and column widths, such as `control` 44, `primaryButton` 52, `setRow` 60, `cell` 38, `line` 1 and the set row's `weightColumn`, `amountColumn`, `rpeColumn` and `tickColumn`. |
| `motion` | `quick` 0.15 s and `standard` 0.25 s. |

## Themes

A theme is a full palette in `tokens.json`: every colour, whether it sits on a light or dark base so the keyboard and system menus match, and how strong the grain is. The two themes today are `light` and `dark`. Adding a theme is adding a block to that file. No view changes.

| Colour | Light | Dark | Used for |
| --- | --- | --- | --- |
| `background` | `#ECE8E1` | `#0F0E0D` | The screen. Warm beige, or warm near-black. |
| `foreground` | `#1C1B19` | `#ECE8E1` | Text, a ticked set, a picked chip and a field with the cursor in it. |
| `foregroundMuted` | `#625E58` | `#9A958C` | Secondary text, such as "Previous" and the settings line. |
| `foregroundFaint` | `#8A857D` | `#847F77` | Placeholder text and unselected tabs. |
| `border` | `#D3CEC5` | `#292623` | Hairlines between rows. |
| `borderSoft` | `#DDD8D0` | `#201E1B` | Quieter hairlines inside a group. |
| `borderControl` | `#CFC9BF` | `#36322E` | The outline on rest, note and brand controls, option chips and the profile photo. |
| `borderStrong` | `#A9A399` | `#4D4943` | The outline of a tick box that is not ticked yet. |
| `surface` | `#E2DDD3` | `#1E1C19` | The soft filled cells behind weight, reps and RPE, and the running workout bar. |
| `accent` | `#8A4F35` | `#C98A6B` | Records, this week's bar and a rising trend on the Stats tab, errors, and delete. |

The grain is `0.06` in light and `0.05` in dark, where grain shows more.

### The theme provider

`ThemeProvider` wraps the app once. It reads the saved choice, "system" or a theme id, turns it into a `Palette`, and puts that palette in the SwiftUI environment. Views read colours with `@Environment(\.palette)` and never name a theme. The provider also forces light or dark to match the theme, so the keyboard and system menus fit.

The choice is saved between launches. Settings has a Theme row that lists system and then every theme in `tokens.json`, and `ThemeMenu` is the same picker as an icon for a toolbar. A saved theme the app no longer knows falls back to the default light or dark theme.

## Motion

Every animation is a spring with no bounce, built on the two motion tokens in `DesignSystem/Motion.swift`. A spring starts from wherever the view is, so tapping again mid-animation redirects it instead of snapping back.

| Name | For |
| --- | --- |
| `Animation.quick` | Press feedback and small state changes, such as a tick box filling in. |
| `Animation.standard` | Panels arriving and leaving, rows being added, scrolling to a set, the settings line opening. |
| `PressStyle` | Press feedback on buttons. `.press` shrinks a control to 97% the moment a finger lands. `.pressRow` dims a full-width row instead, where shrinking would look like the row is moving. |
| `.bottomPanel` | The transition for a panel pinned to the bottom edge, such as the rest timer, the RPE panel and the running workout bar. It rises from the edge and leaves the same way. With Reduce Motion on it only fades. |

The RPE panel and the rest timer share one bottom container. The container rises once when the first of them appears, and switching between the two crossfades in place, so two panels never slide past each other.

## Components sit on top of tokens

Components are the only place tokens get used directly. Screens are built from components. That gives three layers, and each one only knows about the layer below it.

1. Tokens hold the values.
2. Components use tokens.
3. Screens use components.

The components built so far, in `apps/ios/Fatigue/Components` and alongside the screens that own them:

| Component | What it is |
| --- | --- |
| `Hairline` | A thin full-width line between rows, in `border` or `borderSoft`. |
| `PrimaryButton` | The main action on a screen, such as Start workout or Finish. At most one per screen. |
| `OutlinedLabel` | The small outlined controls under an exercise name: rest, note and brand. |
| `NumberCell`, `RPECell`, `TickBox` | One set row: weight and reps in soft filled cells, the RPE cell that opens the RPE panel, and the tick that marks a set done with a light haptic. |
| `LineField` | A form field drawn as a label above the text and a hairline under it, with no box. The line darkens while the field has the cursor. |
| `OptionLabel` | An option chip: outlined when off, filled when picked. Used for muscles, the setting editor's choices, Yes and No on the finish summary, and the brand and metric chips on the exercise page. |
| Chips row | On the exercise page, a row of `OptionLabel` chips. The brand and metric rows scroll sideways when they do not fit and fade at the right edge. Weighted / Raw is the same row without the scroll, and Split by is a menu behind an `OutlinedLabel`. |
| Settings line | An exercise's settings as one quiet line under its name, such as "Seat 4 · Notch 7 · Dead stop", with a small pencil. Tapping it opens the settings into editable rows, then Add setting and Done. With no settings, the line does not show. |
| `SwipeToDelete` | Slide a row left to reveal a trash button behind it. Tap it, or keep sliding past half the row, to delete. The row follows the finger 1:1 and settles with a spring that starts at the finger's speed. Vertical scrolling is never caught by a row. |
| `BottomNav` | A hairline, then one icon and label per tab: Workout, Stats and Profile. The selected tab fills its icon. |
| `ActiveWorkoutBar` | The running workout above the bottom nav while you are elsewhere: its name, how long it has been going and sets done. Tap to go back to it, or delete it. |
| `GrainOverlay` | A faint film grain over a whole screen. The noise is made once and tiled. |
| Sheets and panels | `RPEPanel`, `BrandSheet`, `RestSheet`, `SetupSheet` and `ExercisePicker`. |

## Rules

- No raw colours, font sizes, spacing values or radii in a screen or a component. If the value you need does not exist, add a token.
- A token is added in `tokens.json` first, then used. Nobody edits generated files by hand. `pnpm tokens:build` writes `Tokens.swift`, and `pnpm tokens:check` fails if it is out of date.
- Every theme names exactly the same colours. The build step fails if one is missing or extra.
- If two components need the same new value, that is a sign it should be a token and not a one-off.

## Other platforms

Only the Swift output exists. When Android and the website start, `build.mjs` gains a Kotlin and a CSS output from the same file.
